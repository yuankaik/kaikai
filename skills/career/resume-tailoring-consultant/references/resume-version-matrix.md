# 简历版本矩阵 · 按语境的字段与措辞取舍

单份简历打不了所有战场。**同一段事实，在不同筛选语境下价值符号相反。**
本文件是 §4.5（反过度押注）和 §7.1（三个自曝陷阱）在**多版共存**场景下的补充。

---

## 一、版本矩阵

| 版本 | 投给谁 | 抬头 | 独有字段 | 关键降级项 |
|---|---|---|---|---|
| **通用版** | 外企/民企、猎聘、51JOB、BOSS | 只有岗位 | 不写户籍 | 无（AI 可独立成段） |
| **国企/央企版** | 国企、央企、区政府公示 | 岗位 + **户籍** | 户籍 | **AI/数字化降级** |
| **英文版** | 外企（含外资中国区） | 岗位（英文） | — | **AI 降级为流程改进** |
| **行业定向版** | 高门槛行业 | 岗位 | 行业通行证词 | 行业化过度会劝退其他赛道 |

**版本数由抬头解锁度决定**：抬头只写岗位时，通用版一份通吃所有商业平台赛道，
**不要再按行业做医疗版/工业版**（§4.5）。真正需要独立版本的只有两种情况：
① 国企版（字段规则不同）② 英文版（语言与结构不同）。

## 二、国企/央企版的字段规则

### 必问三项（没有的绝不编，政审会核）

| 项 | 是 | 否 |
|---|---|---|
| 政治面貌 | 党员 → **写**（硬加分，部分岗写"党员优先"） | 群众 → **不写** |
| 职称 | 有 → 写（国企看重职称等级） | 无 → 不写 |
| 户籍 | 本地 → **写进抬头** | 外地 → 也可写，但不如本地加分 |

**"不写"的理由不是谦虚，是止损：**
`政治面貌` 这一栏存在的前提是**有优势可写**。写"群众"= 主动向筛选人声明
"我没有这项加分"，占版面且减分。无职称同理。

### 内容基调替换

| 通用版 | 国企版 |
|---|---|
| 能力 + 迁移 + 数字化 | **稳定 + 合规 + 零事故 + 制度沉淀** |
| "AI自主开发"独立成段 | 降级为项目列表末条 |
| — | **新增"制度与流程建设"独立条** |

**"制度与流程建设"是国企版的隐藏加分项。** 国企（尤其央企）的组织逻辑是
"制度留痕、可交接、可追溯"。一个能写制度文本的主管比只会干活的主管高一个层级。
把散落各条的"编写岗位手册/作业规范/盘库流程/预警流程"聚成独立一条。

**安全条目要加重。** 国企安全生产一票否决，"零工伤"比"库存准确率0.2%"更先被问。
应急演练频次、"零事故"字眼保留并前置。

## 三、AI 卖点为什么必须在国企版和英文版降级

不是藏优点，是**换频道**。

**国企领导视角的反向解读：**
```
"员工自己写程序" → 他哪来的精力？本职工作不饱和？
                 → 搞这套是不是要减少我们的人？
                 → 报表被他一个人包了，以后谁复核？
```

**英文外企的额外风险：**
```
"员工自己用AI处理公司数据" → 用了什么工具？数据合规吗？谁批准的？
                          → 欧美企业 IT governance 严格，
                            可能触碰 data governance 红线
```

**处理方式**：保留事实（2天→2小时），去掉"AI""独立开发""自主"字眼，
改写成中性的 **"流程改进" / "Monthly KPI Reporting Automation"**。
面试时若被问起再展开——但简历不主动招这个问。

⚠️ **与 §4.5 的"数字化必须提显眼位置"不矛盾**：
§4.5 针对**通用版/民企**（同一段是"这人能自己解决问题"，独立成段展示）；
本节针对**国企版/英文版**。**按版本区分，不是一刀切。**

## 四、英文版 vs 中文版 · 结构性差异（不是翻译）

| 维度 | 中文版 | 英文版 |
|---|---|---|
| 零事故记录 | 分散在工作经历各条 | **提成独立加粗句，前置到 Summary**（欧美 EHS 一票否决） |
| N 年留任 | 不主动强调（§7.1） | **正面写进 Summary**——欧美制造业极度看重 retention |
| SOP/制度 | 仅国企版有 | **要有**（德企/外企重 documented procedures） |
| 拼写 | — | 欧资用英式（colour/organised/labelling）；投美资美国总部改美式 |
| 字体栈 | Noto Sans CJK SC | **DejaVu Sans / Liberation Sans / Arial** |
| 字号密度 | 9.3pt / lh 1.45 | **8.6pt / lh 1.33**（同内容需更紧才够 2 页） |

**中英对"14年"的反向处理要点**：中文版不主动强调（会引起"为什么不走"的联想），
英文版放在 Summary 开头（是正面信号）。**同一事实，两个方向。**

**术语换行业标准词，不要直译：**

| 中文 | 英文 |
|---|---|
| 色标管理 | colour-coded labels |
| 受控物料 | controlled materials |
| 差异 | variance |
| 账实一致 | book-to-physical accuracy |
| 呆滞料 | slow-moving materials |
| 首次投产测试 | production-line commissioning |

**英文版要同步中文版的每一处结构改动。** 实测教训：中文版抬头解锁了行业，
英文版仍写着 `Medical Device Manufacturing (GMP-compliant warehousing)` ——
投外企时自己把另外三条赛道劝退。**中英双版抬头必须一起解锁。**

## 五、非相关早期经历的处理（不可留空窗）

用户常想弱化"转行前"的经历。**错。**

```
规则：一段相关 + 两段非相关，远好于"空白"。
      空窗会让 HR 直接疑虑，非相关经历至少是可解释的。
```

三步处理：
1. **全部填上**，不留年份断层
2. **找能力连接点**，不否定过去——例：客服的"准确处理大量事务"与仓储的"差错控制"同源
3. **落到"N年专注"**——把转型讲成主动选择，不是被动流窜

**隐藏加分要主动点出**：早期经历里有外企/大品牌背景（如 SONY、大集团）时，
它证明候选人**早期就在外资体系里工作过**，不是"只在现在这家待过的人"。
投外企时是加分项，面试可以点一句。不要当"不堪回首的前史"糊弄过去。

**面试话术：**
```
"毕业后那几年我在 X 行业，做的是直接面向用户/客户的工作。
 练出来的是两件事：一是处理大量重复性事务的耐心和准确度，
 二是跨部门、跨客户打交道的能力。
 后来进入制造业，我发现仓储管理的核心恰好也是这两件事，
 只是对象从用户变成了物料和库存。之后就一直做下来了，N年。"
```

## 六、生成前必须确认的字段

填招聘平台"在线简历"时，以下**不确认就不能填**（填错要背调返工）：

```
□ 出生年份        （平台藏不住年龄；40+投管理岗是优势，建议如实）
□ 前公司全称       （平台要求准确全名，背调会核）
□ 现公司员工数     （决定"公司规模"字段）
□ 汇报对象职位
□ 下属人数         （正式+外包合计填总管理规模）
□ 期望薪资下限     （谈判底线，只有用户能定）
```

## 七、在线简历字段 ≠ 上传 PDF（关键认知）

```
猎头怎么找到候选人？
  → 搜"在线简历的字段"（职位名/公司名/年限/技能标签/期望薪资）
  → 不是看 PDF

只传 PDF、在线简历留空的后果：
  → 资料不在数据库里 → 猎头搜"仓库经理"永远搜不到 → 等于隐身
```

**技能标签反常识规则：不要填"AI""数字化"。**
这两个标签会把候选人归入 IT/数字化岗位池，**猎头搜"仓库经理"时反而降权**，
而搜"AI"的人是招算法工程师的。标签只填本行词。

**期望薪资按平台分策略（不要一刀切）：**
```
猎聘   → 写明区间（"被猎头主动搜"的一方，写明能过滤够不着的岗）
51JOB  → 留空（海投主场，写了会被"超预算"一键筛掉，失去议价权）
```

**期望职位填4个同义词**（仓储物流经理/仓库经理/仓储经理/物流经理）——
猎头与 HR 用词不统一，多填 = 多倍被搜到概率。

**隐私设置：屏蔽现雇主必须在填其他内容之前做。** 在职者更新简历当天
就可能被现公司 HR/同事刷到。

                     不要误判为字体未嵌入）
